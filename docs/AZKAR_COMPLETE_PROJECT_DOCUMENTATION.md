# توثيق مشروع AZKAR | أذكار

## 1. نظرة عامة

AZKAR تطبيق عربي إسلامي مبني بـ Flutter، يعرض محتوى عاماً وصفحات تذكارية
شخصية يمكن لأصحابها إدارتها ومشاركتها. الواجهة تدعم العربية واتجاه RTL، ويعمل
المشروع على Web وAndroid وiOS. يعتمد تسجيل الدخول والبيانات السحابية على
Supabase؛ أمّا عدّاد التسبيح فمحلي على جهاز أو متصفح كل زائر.

المسارات الأساسية للمستخدم:

1. تصفح الصفحة الرئيسية والمحتوى المنشور.
2. تسجيل الدخول أو إنشاء حساب من أربعة حقول: الاسم والبريد وكلمة المرور
   وتأكيدها.
3. استعادة كلمة المرور عبر البريد.
4. فتح لوحة التحكم وإدارة الصفحة والمحتوى والمظهر.
5. نشر الصفحة ثم مشاركة رابطها العام `/m/:slug`.

## 2. البنية

- `lib/main.dart`: تهيئة Flutter، إعداد Supabase، اختيار مسارات الويب، وتحميل
  الخط العربي الافتراضي.
- `lib/app.dart`: الثيمات وتهيئة التطبيق.
- `lib/core/config/app_config.dart`: قراءة Dart defines والتحقق منها وبناء
  الروابط العامة.
- `lib/core/routing/app_router.dart`: مسارات التطبيق، ومنها `/login`,
  `/register`, `/reset-password`, `/m/:slug` و`/m/:slug/:type`.
- `lib/features/account`: المصادقة ولوحة مالك الصفحة وإعداداتها.
- `lib/features/memorial`: نموذج الصفحة، التحقق من slug ومستودع Supabase.
- `lib/features/content`, `home`, `admin`, `sharing`: المحتوى والصفحة الرئيسية
  والإدارة والمشاركة.
- `assets/data` و`assets/fonts` و`assets/branding`: بيانات محلية وخطوط وهوية
  AZKAR.

في الويب يستخدم التطبيق مسارات URL عادية عبر `usePathUrlStrategy()`، لذلك تكون
الرابطة `/m/slug` مباشرة بدلاً من `/#/m/slug`. يحتاج المضيف إلى إرجاع `index.html` لطلبات التنقل التي لا تطابق ملفات ثابتة.
Workers Static Assets يحقق ذلك عبر
`assets.not_found_handling: "single-page-application"` في `wrangler.jsonc`.
الملفات الموجودة تُخدم كما هي؛ لا نعيد كتابة طلبات JS أو الخطوط أو الصور، ولا
نستخدم إعدادات Pages أو ملف `_redirects`.

## 3. الميزات

| الميزة | الوضع الحالي |
|---|---|
| تسجيل موحّد للمستخدمين ومشرفي المنصة | موجود عبر Supabase Auth |
| التسجيل، تسجيل الدخول، واستعادة كلمة المرور | موجود؛ التسجيل محكوم بعلم التحقق من المخطط |
| صفحة تذكارية لكل مالك | ينشئها مشغّل Supabase الموجود عند إنشاء المستخدم |
| عنوان الصفحة والـslug والنشر | إعدادات الصفحة في لوحة المالك، لا التسجيل |
| أذكار، قرآن، حديث، أدعية، تسبيح، فيديوهات، وإهداءات | أنواع محتوى موجودة في التطبيق والمخطط |
| تخصيص الصفحة الرئيسية والمظهر | موجود عبر بطاقات الصفحة وإعدادات الثيم |
| لوحة المالك ولوحة مشرف المنصة | موجودتان بصلاحيات منفصلة |
| المشاركة والنسخ | `share_plus` للمشاركة، مع أهداف وروابط ونسخ بديل |
| عدّاد التسبيح | محلي؛ لا يرسل عدّادات للـbackend |
| Open Graph عام | عنوان ووصف وصورة الشعار في HTML؛ بيانات ثابتة للموقع |
| معاينة اجتماعية مختلفة لكل صفحة | غير منفذة؛ تحتاج معالجة server-side اختيارية |

هذا الجدول يصف ما وجد في الشيفرة والمخطط المرفق؛ لا يعني أن كل تكامل خارجي
اجتاز اختبار قبول حيّاً.

## 4. قاعدة البيانات وعزل المستخدمين

المخطط المرجعي في
[`20261030_multi_tenant_foundation.sql`](../supabase/migrations/20261030_multi_tenant_foundation.sql)
يتضمن الجداول التالية:

- الهوية والملكية: `profiles`, `memorial_pages`, `admin_profiles`.
- المحتوى: `azkar`, `quran_verses`, `hadith`, `duas`, `tasbeeh_cards`,
  `youtube_videos`, `dedications`.
- الصفحة والمظهر والتدقيق: `homepage_cards`, `theme_settings`,
  `admin_audit_logs`.

المحتوى الشخصي يشير إلى `memorial_pages` عبر `page_id`، وصفحة المالك مرتبطة
بمعرّف Auth عبر `owner_user_id`. بطاقات الصفحة تشير إلى محتوى من نوع محدد،
وتتحقق دوال قاعدة البيانات من تطابق نوع المحتوى ومعرّفه والصفحة. إعداد الثيم
مرتبط بالصفحة، وتحتوي سجلات الإدارة على سجلات التدقيق.

المخطط يفعّل RLS على الجداول ويعرّف سياسات ملكية وقراءة عامة: الصفحة تُقرأ
للمالك أو عندما تكون منشورة؛ ومحتوى الصفحة لا يظهر للزوار إلا إذا كان المحتوى
والصفحة منشورين. البطاقات العامة المفعّلة يجب أن تشير إلى محتوى منشور صالح،
والثيم الشخصي للزائر متاح عند نشر الصفحة. الكتابة الشخصية للمستخدم الموثّق
مقيّدة بصفحته، ومحتوى المنصة العام محكوم بصلاحيات مشرف المنصة. توجد منح
صلاحيات على أعمدة محددة إلى جانب سياسات RLS.

**حدود التحقق:** راجعنا تعريفات المخطط الموجودة في المستودع، ولا ننفّذ SQL
أثناء إعداد النشر. لا يمكن لهذا الفحص وحده إثبات أن إعداد Supabase الحي يطابق
الملف أو أن سلوك RLS مقبول. يلزم اختبار مجهول الهوية واختبار مالكين منفصلين
باستخدام حسابات اختبار معتمدة قبل تفعيل التسجيل العام. لا تستخدم مفتاح
`service_role` في Flutter ولا في أدوات المتصفح.

## 5. المصادقة والتفويض

- Supabase Auth هو موفر الحسابات. شاشة التسجيل تعرض أربعة حقول فقط.
- التسجيل يرسل الاسم وعنوان صفحة افتراضي إلى بيانات Auth؛ لا يرسل slug.
- مشغّل `azkar_provision_owner_page` هو آلية إنشاء الملف والصفحة، فلا تضف
  مسار provisioning ثانياً.
- الـslug الناتج ثابت وفريد، ثم يستطيع المالك تغييره من إعدادات صفحته.
- الصفحة تبدأ غير منشورة. لا تظهر للزوار حتى ينشرها مالكها.
- تسجيل الدخول موحّد. صلاحية مشرف المنصة تعتمد على سجل إداري نشط، لا على
  بيانات التسجيل أو metadata.
- استعادة كلمة المرور تستخدم رابط إعادة توجيه مبنياً على `PUBLIC_BASE_URL`
  عند ضبطه.
- `AZKAR_AUTH_SCHEMA_VERIFIED` حارس تشغيلي للبناء والتسجيل، وليس بديلاً عن RLS.

## 6. الإعدادات والأسرار

يقرأ التطبيق القيم عبر `String.fromEnvironment` و`bool.fromEnvironment`؛ ولا
يقرأ ملفات `.env`. التشغيل المحلي يستخدم `config/dev.json` مع:

```powershell
flutter run -d edge --dart-define-from-file=config/dev.json
```

ملف إعداد الإنتاج المحلي هو `config/production.json`، غير المتعقب في Git.
ابدأ من `config/production.example.json` بعد إنشاء مشروع الاستضافة والحصول على
عنوانه الفعلي. يحتوي على:

- `SUPABASE_URL`: عنوان مشروع Supabase.
- `SUPABASE_ANON_KEY`: مفتاح anon/publishable العام فقط.
- `AZKAR_DEMO_MODE`: يجب أن يكون `false`.
- `AZKAR_AUTH_SCHEMA_VERIFIED`: يظل `false` حتى إتمام التحقق المطلوب.
- `PUBLIC_BASE_URL`: أصل موقع HTTPS الفعلي بلا مسار.

تُضمّن Dart defines في ملفات الويب المجمّعة؛ هي ليست مخزناً للأسرار. المفتاح
العام وحده مناسب لتطبيق العميل بشرط صحة RLS. لا تضع service-role أو أي مفتاح
سري في الملف أو الشيفرة أو مستودع Git. لا نغيّر إعداد التطوير بإعداد الإنتاج.

## 7. الروابط العامة والنشر

- المسار العام: `/m/:slug`، والمسارات الفرعية مثل `/m/:slug/azkar`.
- `PageSlug` يطبّع ويتحقق من slug؛ قاعدة البيانات تفرض التفرد والقيود أيضاً.
- `SupabaseMemorialPageRepository.fetchPublishedBySlug` يطلب الصفحة المطابقة
  التي تحمل `is_published = true`. لا يتطلب المسار جلسة دخول.
- لا توجد نتيجة أو صفحة غير منشورة: رسالة عربية «الصفحة غير متاحة» من دون
  تفاصيل قاعدة البيانات. الخطأ المؤقت يعرض شاشة خطأ مع إعادة المحاولة.
- رابط المشاركة يبنى مركزياً من `PUBLIC_BASE_URL + /m/ + slug`، بينما مسار
  التطبيق الداخلي يبقى `/m/:slug`. إذا لم يُمرر `PUBLIC_BASE_URL`، يستخدم
  رابط المشاركة أصل Worker الحالي. لا يؤثر هذا الافتراضي على تحويل استعادة
  كلمة المرور؛ عند غياب الإعداد الصريح يستخدم Supabase عنوان الموقع المضبوط.
  لا تنشر رابط صفحة غير منشورة باعتباره وصولاً عاماً.
- رؤوس HTML توفر معاينة عامة للموقع. معاينة الصفحة الخاصة لا تتغير عند زيارة
  مسار Flutter لأن البيانات تُجلب بعد تحميل JavaScript.

## 8. النشر على Cloudflare Workers

التحضير المحلي موجود في:

- `scripts/build_web_production.ps1`
- `scripts/deploy_cloudflare.ps1`
- `.github/workflows/deploy-worker.yml`
- `wrangler.jsonc`
- `docs/CLOUDFLARE_DEPLOYMENT.md`
- `docs/DEPLOYMENT_CHECKLIST.md`

الاستضافة النشطة هي Worker موجود اسمه `azkar-sadaqa` على:
`https://azkar-sadaqa.mohamed-fooda-mtf.workers.dev`. إعداد Wrangler يرفع
`build/web` فقط. GitHub Actions يثبت Flutter 3.47.7 وWrangler 4.156.0، يشغل
التحليل والاختبارات، يبني Flutter Web release، ثم ينشر Worker بعد موافقة
GitHub environment `production`. يجب فصل Workers Build القديم قبل تفعيل هذا
المسار لتجنب النشر المكرر. لا ينشئ workflow Worker جديداً.

التدفق المحلي اليدوي الاحتياطي يستخدم `scripts/deploy_cloudflare.ps1`، الذي
يشغّل build إنتاجاً جديداً ثم يجري dry-run ويطلب تأكيداً صريحاً قبل النشر.
يمكن تشغيل `scripts/build_web_production.ps1` منفرداً للتحقق من build فقط.
لا تستخدم النشر اليدوي بالتوازي مع نشر آلي. إعدادات Cloudflare Pages ليست
مسار النشر المختار.

## 9. الاختبارات

- `flutter analyze` و`flutter test` للتحليل واختبارات الوحدات والواجهات.
- اختبارات المسارات تغطي الوصول العام إلى صفحة memorial دون جلسة، والتسجيل
  بأربعة حقول، والرجوع والتنقل.
- اختبارات إعدادات الصفحة تغطي العنوان والـslug والنشر والتجاوب.
- الاختبارات المحلية لا تثبت سياسات RLS على Supabase الحي.
- بعد النشر اختبر الصفحة الرئيسية، المصادقة، استعادة كلمة المرور، روابط
  memorial المباشرة، التحديث، الرجوع/التقدم، الصفحات المنشورة وغير المنشورة،
  المشاركة، واتجاه RTL على الهاتف والحاسوب.
- لم يُجر اختبار Cloudflare حي أو إنشاء حساب أو اختبار تسجيل مستخدم حقيقي
  كجزء من إعداد المشروع.

## 10. الصيانة واستكشاف الأعطال

- شغّل `flutter pub get` بعد تغيير الاعتمادات فقط.
- لبناء الموقع بعد تحديث الكود، راجع الإعداد أولاً ثم شغّل
  `scripts/build_web_production.ps1`. اختبر التوجيه المحلي باستخدام
  `npx.cmd --yes wrangler@4.156.0 dev --local --ip 127.0.0.1 --port 8787`.
  النشر الأساسي يتم من GitHub Actions بعد نجاح التحليل والاختبارات وموافقة
  بيئة الإنتاج.
- إذا ظهرت صفحة بيضاء، تحقق من سجل المتصفح، تهيئة Supabase، مسار `base href`
  وملفات Flutter التي أعادها المضيف.
- إذا فشل `/m/slug` مباشرة، تحقق من Path URL Strategy وإعداد
  `assets.not_found_handling` ومن أن Cloudflare نشر `build/web` لا `web/`.
- إذا لم تظهر البيانات، افحص حالة النشر وسياسات RLS وإعداد Supabase دون كشف
  تفاصيل الخطأ للمستخدم العام.
- عند ظهور ملفات قديمة بعد نشر، اختبر في نافذة خاصة أولاً. لا تضف Cache Rules
  مخصصة دون حاجة؛ قواعد الكاش المخصصة قد تسبب ملفات قديمة أو تتجاوز وظائف
  التوجيه.
- اتبع سياسة نسخ احتياطي مناسبة لبيانات Supabase وتحقق من إمكان الاستعادة؛
  نشر ملفات الويب لا ينسخ قاعدة البيانات.

## 11. القيود المعروفة

1. hostname الـWorker موجود، لكن النسخة التي جرى فحصها تُرجع قالب HTML الخام؛
   يلزم نشر Flutter build صحيح وموافقة صاحب المشروع.
2. ملف `config/production.json` غير موجود محلياً؛ البناء الإنتاجي الحقيقي
   يتطلب إعداد GitHub environment secrets.
3. تعريفات RLS في الملف موجودة، لكن اختبار عبور المستأجرين على المشروع الحي
   ما زال مطلوباً.
4. معاينات مشاركة الصفحات الفردية وبيانات SEO الديناميكية غير مدعومة حالياً.
5. لا يضمن Flutter SPA وحده معاينات WhatsApp/Facebook؛ معظم برامج الزحف لا
   تنفذ JavaScript كمتصفح كامل.

## 12. تحسينات مستقبلية

- ربط نطاق مخصص بعد الإطلاق الاختباري.
- Worker اختياري لإرجاع HTML وOpen Graph ديناميكيين للزاحف،
  مع قراءة المنشور فقط، وفشل آمن، ومراجعة حدود الاستخدام والتخزين المؤقت.
- إضافة sitemap وrobots بعد تحديد سياسة الفهرسة وhostname.
- تحسين قياسات الأداء وSEO بعد اختبار ميداني على أجهزة واتصالات فعلية.
